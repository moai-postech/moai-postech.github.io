§ Splitting the Work

One Sensor ReadingEach row records one temperature measurement from one machine

Row 3 says that machine M1 was measured at 85°C

Filtering Hot ReadingsFor one day of readings, keep every measurement at 80°C or above

The condition keeps five of the nine readings

Counting by MachinePut the same machine name together, then count the readings in each group

M1 has three hot readings; M2 and M3 each have one

Why Many MachinesDistributed processing divides work across computers when one computer is insufficient

Different computers read different rows to answer the same question

Scale Up or Scale OutScale up adds resources to one machine; scale out adds machines

Extra machines add capacity and coordination work

Storage and ComputeStorage keeps the files; workers are processes that read files and calculate results

Durable input and temporary computation have different jobs

Input PartitionsA partition is one piece of data that can be processed independently

M1 appears in all three input partitions

Partitions, Tasks and WorkersThe data piece, the computation and the process doing it have different names

A task applies the filter to one partition on a worker

Local FilteringEach computer can keep its hot readings without checking the other pieces

Two, one and two rows remain in the three partitions

§ Combining the Results

Local Counts Are Not the Final AnswerA global group must combine information from different partitions

Three local M1 counts must become one global count

The Grouping KeyA key is the value used to decide which records belong in the same group

Different reading IDs share the same machine key, M1

ShuffleA shuffle redistributes data across partitions for a key-based operation

Filtering stays local; a global grouping may move data

A Worker Can Fail

Retry needs available source data and a repeatable computation

The MapReduce PatternMapReduce organizes this job as per-row work, key grouping and per-group work

Follow the same nine readings through map, shuffle and reduce

One Reading, One CountIn this MapReduce example, map turns each hot reading into (machine, 1)

The machine names the group; 1 counts one reading, regardless of its temperature

Map: Keep and EmitFor each row at 80°C or above, map outputs (machine, 1); other rows produce nothing

The value 1 represents one retained reading

Shuffle: Bring the Same Key TogetherEvery value for M1 meets in the same key group

The shuffle crosses the original input-partition boundaries

Reduce: Add Within Each KeyReduce turns the values of each key into one result

Five readings become three grouped counts

Demo: Follow the Grouped CountBrowser simulation: predict the next step before revealing it

Track M1 from three input partitions to one result

Answer: Follow the Grouped CountMap emits five pairs, shuffle forms three keys, reduce returns three counts

The output counts sum to five retained readings

§ Describing the Job

From MapReduce to SparkSpark lets us describe several table operations together in one execution plan

Multi-step work motivates an engine that connects operations in one plan

SparkSpark runs table operations across data pieces; it handles the distributed work

The storage keeps the data; Spark executes the work

A DataFrame: One Table, Many Piecesevents is our input DataFrame: one table whose rows can be stored in different pieces

One events DataFrame, three illustrated input partitions

Start a Spark SessionPySpark is the Python interface to Spark; spark is our entry point for reading data

from pyspark.sql import SparkSession

# Create or reuse the Spark entry point named spark
spark = (SparkSession.builder
    .appName("hot-readings")
    .getOrCreate())

From a CSV File to a TableA comma-separated values (CSV) file stores one table row per line

The header names columns; the schema gives those columns their value types

Read Files with a SchemaA schema defines the columns: id is a whole number, machine is text, temp is numeric

events = (spark.read
    .schema("id INT, machine STRING, temp DOUBLE")
    .option("header", True)  # First CSV row contains column names
    .csv("raw/readings/2026-11-05/"))  # Folder for one day

Describing and Running WorkLazy evaluation delays result computation until an action requests it

A transformation defines a DataFrame; an action returns or saves a result

Filtering a DataFramefilter keeps matching rows; hot names that DataFrame; show() requests its rows

hot = events.filter(events.temp >= 80)
hot.show()  # Request the rows
The selected rows keep their original id, machine and temperature columns

Counting Groups in a DataFramegroupBy chooses the grouping column; count defines one row count for each group

# Group rows by machine, then count each group
hot_counts = hot.groupBy("machine").count()
hot_counts.show()  # Request the grouped rows
hot_counts describes three grouped rows rather than five individual readings

The Same Question in SQLWHERE keeps the hot rows; GROUP BY machine and COUNT(*) count them per machine

events.createOrReplaceTempView("events")  # Name the table for SQL

hot_counts = spark.sql("""
    SELECT machine, COUNT(*) AS count
    FROM events
    WHERE temp >= 80
    GROUP BY machine
""")
hot_counts.show()  # Request the same three grouped rows

§ Executing and Saving

Two Meanings of count()The object before count() determines whether it returns a number or defines grouped rows

Five hot readings and three grouped result rows answer different questions

Driver and ExecutorsSpark calls its coordinator the driver and its worker processes executors

One program can coordinate work across several executor processes

A Grouped Count Needs a MergeSpark can combine local partial counts before moving them by key

Local aggregation can reduce traffic; the global merge still matters

Demo: Change the Query PlanBrowser simulation: change the condition, predict the rows, then run an action

The grouping choice changes the meaning and number of output rows

Answer: Change the Query PlanAt 85, one M1 reading drops out; the other machines remain

ConditionWith groupingWithout grouping
temp >= 80M1=3, M2=1, M3=15 readings
temp >= 85M1=2, M2=1, M3=14 readings
temp >= 1000 rows0 rows
Four retained readings produce three grouped rows

Cache Reused DataWhen two actions need the same rows, caching keeps computed pieces for reuse

Caching requests reuse; actions populate the cached data

Reuse One Filtered DataFrameCache only when repeated reuse justifies its storage cost

hot = events.filter(events.temp >= 80).cache()

hot.count()  # Returns 5; also computes and keeps the hot rows
hot.groupBy("machine").count().show()  # Reuse kept rows

hot.unpersist()  # Release the cache when finished

Recover Missing WorkLineage is the recorded path from input to result, used to recompute lost work

Independent filters rebuild the lost partition; dependencies determine wider retries

Caveat: Uneven WorkUneven data creates uneven work; this imbalance is called data skew

More workers alone do not remove a heavily loaded key

Caveat: Collecting Too Muchcollect() gathers every result row into the driver; a large result may not fit

Check the result size before turning distributed data into a local object

Write Distributed Resultswrite saves the table; Parquet is a column-based file format for the saved data

(hot_counts.write
    .mode("errorifexists")  # Stop if the path exists
    .parquet("output/hot_counts/run_2026_11_05/"))

A Dataset Is Often a FolderDifferent data pieces can be saved as separate files and read together as one table

Several part files can represent one logical result table

Caveat: Overwriting the Wrong PathWriting one day of results to the whole history folder can replace other days

A one-day input does not make a whole-path overwrite safe

One Complete Spark JobDefine a bounded input, transform it, then save the result once

events = (spark.read.schema("id INT, machine STRING, temp DOUBLE")
    .option("header", True).csv("raw/readings/2026-11-05/"))

hot_counts = (events.filter(events.temp >= 80)
    .groupBy("machine").count())

(hot_counts.write.mode("errorifexists")
    .parquet("output/hot_counts/run_2026_11_05/"))
