## 요청
교수가 Members 비밀번호를 한 번 입력하면 계속 반영되게 해 달라고 요청했다.

## 반영 내역
- 성공적으로 복호화한 뒤 내보내기 불가능한 CryptoKey와 키 생성 매개변수만 IndexedDB에 저장한다. 비밀번호와 복호화 명단은 저장하지 않는다.
- 같은 브라우저에서 다시 방문하면 저장한 키로 현재 암호문을 열어 최신 명단을 표시한다. Lock은 저장한 키와 명단 DOM을 지운다.
- 명단 갱신 시 비밀번호가 같으면 기존 salt·PBKDF2 반복 수를 유지한다. IV는 새로 만든다. 비밀번호가 바뀌면 salt를 교체하고 기존 브라우저 키는 다시 사용할 수 없다.
- 저장을 지원하지 않는 브라우저에서는 현재 방문 동안 열고 저장 실패를 표시한다.
- Members 안내문과 STUDY 규칙을 현재 동작으로 갱신했다. 원본 복구는 Git 직전 커밋.

## 검증
- 읽은 규칙: 상위·저장소 AGENTS.md, 전역 secrets·workflow·memory-location, STUDY·기존 Members 검사와 가상 명단 검수 경로.
- 네 화면 폭에서 표·잠금 검사 통과. 별도 임시 브라우저 프로필에서 잘못된 비밀번호, 새로고침, 페이지 이동, 새 탭, 브라우저 재시작, 명단 갱신, 비밀번호 변경, Lock 후 재시작까지 검증했다.
- 저장 항목이 iterations·salt·비추출 CryptoKey뿐이며 localStorage·sessionStorage가 비어 있음을 확인했다.
- IndexedDB 미지원과 CryptoKey 저장 오류를 가상으로 발생시켜, 현재 방문 열람과 Lock이 멈추지 않는지 확인했다.
- 동기화 도구의 실제 암호화 코드에 가상 데이터를 넣어 동일 명단 유지·명단 변경 시 salt 유지/새 IV·비밀번호 변경 시 salt 교체를 확인했다.
- JavaScript 문법·diff·changelog 검사와 Actions 빌드·빠른 검사·배포를 확인한다.

## 기각한 안과 이유
- 비밀번호 또는 복호화 명단 저장: 비밀번호 없이도 열람 상태를 유지할 수 있으므로 저장하지 않는다.
- 매번 명단 갱신 때 salt 교체: 비밀번호가 같아도 저장한 브라우저 키가 무효가 되므로, 같은 키를 쓰고 IV만 갱신한다.
