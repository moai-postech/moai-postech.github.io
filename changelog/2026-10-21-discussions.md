# 2026-10-21 의견 충돌 안건(discussions) 관리
작성자: Sangwoo Mo(moai-postech) | 대상: AGENTS.md, discussions/, tools/check_changelog.py, _config.yml | 도구: Claude Code

> **한줄 결론: 다른 사람의 결정과 부딪히는 수정은 바로 반영하지 않고 `discussions/` 안건으로 올려 교수·랩 미팅이 결정하게 했다. 열린 안건의 대상 파일은 결정 전까지 검사에서 막힌다.**

## 요청

여러 학생이 고치다 보면 의견이 부딪힐 수 있으니, 그런 경우는 바로 반영하지 말고 논의할 사항을 따로 모아 교수와 멤버가 보고 결정할 수 있게 한다.

## 반영 내역

- `AGENTS.md` 에 "논의가 필요한 수정" 절을 추가했다. 판정 기준 네 가지(되돌리기, 열린 안건과 겹침, 모두에게 걸리는 결정, 의견이 갈림), 바로 반영해도 되는 것, 안건 양식, 결정과 반영 절차가 있다. 고치는 절차 2단계에 판정을 넣었다.
- `discussions/index.md`(안건 표: 날짜, 안건, 제안자, 대상, 상태, 결정 changelog)를 만들었다. 상태는 `논의 중`, `결정됨`, `보류`.
- `tools/check_changelog.py`: 안건만 올리는 push 는 changelog 없이 통과한다. 안건 파일 이름, 상태 줄, index 링크를 검사한다. 열린 안건의 `대상:` 줄에 적힌 파일을 같은 push 에서 안건 상태 변경 없이 고치면 실패한다.
- `_config.yml` 의 exclude 에 `discussions` 를 더해 사이트에 나가지 않게 했다.
- 시험: 안건만 올림(통과), 열린 안건 대상 수정(실패), 결정 후 상태 변경과 함께 반영(통과), 잘못된 상태 값(실패).

## 기각한 안과 이유

- **GitHub Issues 로 안건 관리**: 댓글 UI 는 편하지만 에이전트마다 GitHub 접근 방식이 달라 저장소 파일만 읽는 에이전트는 안건을 못 본다. changelog 와 같은 파일 방식으로 두면 어떤 에이전트든 `AGENTS.md` 만 따라 같은 판단을 한다.
- **모든 수정을 PR 리뷰로 강제(브랜치 보호)**: 오타나 본인 정보 같은 작은 수정까지 막힌다. 부딪히는 수정만 골라 안건으로 돌린다.
- **충돌 여부를 스크립트로 전부 판정**: "되돌리기"나 "의견이 갈림"은 기계적으로 가를 수 없다. 스크립트는 열린 안건의 대상 파일만 막고, 나머지 판정은 `AGENTS.md` 기준을 읽은 사람과 에이전트가 한다.
