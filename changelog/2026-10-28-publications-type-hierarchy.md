# 2026-10-28 Publications 글자 위계와 venue 정리
작성자: Sangwoo Mo(sangwoomo) | 대상: Publications > By Year | 도구: Codex, frontend-design 스킬

> **한줄 결론: venue 배지를 없애 제목·저자·게재 정보의 시작선을 맞추고, 제목 17px와 보조 정보 15px로 글자 위계를 정리했다.**

POSTECH 요구사항: 영향 없음.

## 요청
교수가 venue의 글꼴과 본문에서 따로 뜨는 느낌을 지적하고 디자이너 스킬로 개선을 요청했다. 교수 본인의 Publications 디자인 조정 요청을 이번 변경의 근거로 삼았다.

## 디자인 결정
- Pretendard와 기존 팔레트를 유지: 흰 바탕 #ffffff, 본문 #172b40, 보조 #596574, 강조 #a61955.
- 제목은 본문 크기 17px·600, 저자와 게재 정보는 기존 공통 보조 크기 15px·400. 새 크기나 글꼴은 추가하지 않는다.
- 한 논문은 제목, 저자, 게재 정보의 세 줄로 읽힌다. 각 줄의 왼쪽 시작선을 맞추고 venue와 자료 링크 사이는 24px로 구분한다.

## 반영 내역
- `_themes/wide/includes/theme.css`: 저자·메타 역할 토큰을 공통 보조 크기에 연결. 목록 venue의 배경·안쪽 여백·둥글기 제거, 행간 상속. 메타 그룹 사이 24px, 줄바꿈 간격 4px.
- `tools/check_format.js`: 제목과 보조 정보의 역할별 크기를 검증하도록 기존 동등 크기 조건 변경.
- `tools/check_typography.js`: venue 배경·들여쓰기와 제목 시작선 일치 검사.
- 논문 데이터·순서·번호·링크는 그대로다. Oral·Spotlight·수상 표시는 기존 강조색을 유지한다.

## 검증
- Jekyll 빌드 성공. 로컬의 기존 Ruby 3.3 gem 캐시와 Ruby 호환 shim 사용.
- 형식: 13개 페이지 × 1440·1280·768·390·320px 통과.
- 타이포그래피: 26개 페이지, 177개 상태·폭, 텍스트 19,645개 통과.
- POSTECH: 연구실 14개·강의 12개 페이지 × 1280·390px 통과.
- 실제 브라우저에서 WACV 트랙과 NeurIPS 논문 목록의 정렬·글자 위계를 확인.
- 백업: Git 이력. 다른 세션의 수정과 섞이지 않도록 원격 main 기반 별도 worktree에서 반영.

## 기각한 안과 이유
- 다른 글꼴·이탤릭 venue: 사이트 전체의 Pretendard와 달라 따로 뜨는 느낌을 키운다.
- venue를 더 진한 배지나 강조색으로 표시: 제목보다 먼저 눈에 들어와 논문 목록의 위계가 약해진다.
- 논문마다 카드·구분선·이미지 추가: 긴 논문 목록을 훑는 속도가 떨어지고 기존 넓은 목록 구조와 맞지 않는다.

## 이어서: 사이트 전체 글자 크기 축소 (교수 요청)

교수: 폰트가 살짝 크게 느껴져 전체적으로 조금 줄이고, 세부 판단은 맡긴다고 요청.

- 사이트 공통 크기만 조정: 보조 15→14px, 본문·논문 제목 17→16px, 묶음 제목 20→19px, 절 제목 28→26px, 첫 화면 큰 글자 34–48→32–46px.
- 작은 글자는 13px로 유지. Pretendard와 굵기·행간 비율·간격·폭은 기존 역할 토큰을 따른다.
- Publications의 최종 크기는 제목 16px, 저자·게재 정보 14px다. 앞 절의 17/15px는 첫 반영의 값이다.
- 기각: 배율로 페이지 전체 축소. 버튼·사진·간격까지 함께 줄어들기 때문에 글자 크기 토큰만 조정했다.
- 재검증: Jekyll 빌드, 형식 13페이지×5폭, 타이포그래피 26페이지·177상태·19,582텍스트, POSTECH 검사 모두 통과. 실제 Home과 Publications 화면에서 축소 후 위계 확인.

## 이어서: venue와 추가 정보의 간격 재검토

교수: venue와 아래 추가 정보가 멀어 보이고 글꼴도 달라 보인다며 디자이너 관점의 재검토 요청.

- 운영 브라우저 실측: 제목·저자·venue·자료 링크 모두 Pretendard. venue와 링크는 14px·400·행간 21px·기본 자간으로 동일하다. 다른 폰트를 사용하지 않는다.
- venue와 자료 링크 그룹 사이 24→12px. 링크끼리의 간격도 12px이므로 하나의 게재 정보 줄로 읽히게 한다.
- 수상 정보 줄의 margin-top 4px 제거. 항목의 공통 줄 간격 4px만 남겨, 이중으로 벌어진 세로 간격 8→4px.
- 기각: venue 전용 글꼴·기울임·새 배지·추가 구분선. 정보 사이의 결속 문제가 핵심이므로 글꼴과 장식을 늘리지 않는다.
- 백업은 Git 이력. 기존 논문 데이터와 사이트 공통 글자 크기는 유지.
- 검증: Jekyll 빌드, 형식 13페이지×5폭, 타이포그래피 26페이지·192상태, POSTECH 검사 통과. 실제 브라우저에서 2026년 논문·Oral과 수상 정보 줄을 확인.

## 이어서: venue의 시각적 위계 강화

교수: 간격과 venue의 가독성을 비판적으로 검토하고, 과하지 않으면 venue에 bold를 조금 더 주어도 좋다고 요청.

- 비판적 검토: 간격 12px는 같은 줄의 정보를 묶기에 적절하다. 다만 venue와 자료 링크가 모두 14px·400이라 빠르게 훑을 때 학회명이 충분히 구분되지 않는다.
- venue만 Pretendard 600으로 조정. 제목은 16px·600, venue는 14px·600, 저자·자료 링크는 14px·400으로 위계를 유지한다.
- 색·배경·크기·간격은 유지. Oral·Spotlight의 강조색도 유지한다.
- 기존 타이포그래피 검사는 venue의 600 굵기와 제목보다 작은 크기를 확인하도록 변경.
- 기각: 700 bold, 크기 확대, 배지 복원. 제목과 경쟁하며 학회명보다 장식이 먼저 보일 수 있다.
- 백업: Git 이력.
- 검증: 실제 2026년 논문 목록에서 600이 제목보다 낮은 위계를 유지하며 venue 식별을 개선하는 것을 확인. Jekyll, 형식 13페이지×5폭, 타이포그래피 26페이지·192상태, POSTECH 검사 통과.

## 이어서: 모바일 상단 여백과 정보 그룹 간격

교수: 검수에서 남은 모바일 상단 공간 문제를 반영하도록 요청. 이어서 venue→arXiv와 arXiv→code 간격의 균형을 질문.

- 모바일(680px 이하) 공통 상단 여백 조정: 헤더 위 padding 24→16px, 하위 탭 위 32→16px, 탭→소개 및 소개→첫 절 32→16px.
- `--subnav-start` 역할 토큰 추가. 데스크톱은 기존 32px, 모바일은 16px. `--page-start`도 모바일 값만 16px.
- 로고 크기, 메뉴의 44px 터치 높이, 폰트, 논문 내부·항목·연도 간격은 유지.
- 운영에서 venue→arXiv와 arXiv→code의 상자 간격은 모두 12px임을 실측. 정보 그룹을 구분하기 위해 최종 venue→자료 링크는 16px, 자료 링크끼리는 12px로 조정. 이전 24px보다 좁고 링크끼리보다 넓게 함.
- 기각: 메뉴 숨김·축소, 소개 삭제, 논문 폰트 추가 축소. 탐색과 읽기 편함을 보존하면서 상단의 빈 공간만 줄임.
- POSTECH 요구사항: P2·P8 확인. 워드마크·연구실 로고·대표홈 링크·비례 유지, 여백만 조정.
- 백업: Git 이력.
- 검증: 390px·320px 모두 첫 논문 제목의 시작 위치 397.56→341.56px(56px 단축), 가로 넘침 없음. 형식 13페이지×5폭, 타이포그래피 26페이지·192상태, POSTECH 검사 통과. 데스크톱 상단 여백 값은 유지.
