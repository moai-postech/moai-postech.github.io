# push 를 빠르게

- 날짜: 2026-11-10
- 작성자: Sangwoo Mo(sangwoomo)
- 요청: 교수 "검사가 왜 이렇게 오래 걸리나, 심플하게 빨리빨리 푸시되도록"

## 잰 것

- push 전 훅 전체 2.4초(커밋 빌드 1.4초, `check_changelog.py` 0.6초). 훅은 느리지 않았다.
- 느렸던 것은 에이전트가 push 전에 iCloud 작업 폴더에서 따로 돌린 `tools/jekyll.sh build`(306초)와 push 뒤 CI(`format` 약 2분)를 기다린 것.
- 작업 폴더 빌드가 느린 원인: Jekyll 은 gitignore 를 모르고, gitignore 된 `visual-review-bundle/`(153MB)까지 iCloud 에서 읽어 복사했다.

## 바꾼 것

- `_config.yml` exclude 에 `visual-review-bundle`. 작업 폴더 빌드 2.3초.
- `AGENTS.md` 검사와 배포: "push 한 뒤 `gh run watch` 로 본다"를 "커밋하고 바로 push, 따로 빌드하지 않고 CI 를 기다리지 않는다. 결과는 다음 작업 시작 때 `gh run list` 로 본다"로 바꿈. 큰 로컬 폴더는 exclude 에 넣으라는 줄 추가.

## 기각한 안

- 훅에서 빌드를 빼는 안: 훅은 2초라 빼도 빨라지지 않고, 깨진 커밋을 막는 유일한 장치라 둔다.

- POSTECH 요구사항: 영향 없음(exclude 한 줄만 더함, `postech`·`footer` 값은 그대로)
