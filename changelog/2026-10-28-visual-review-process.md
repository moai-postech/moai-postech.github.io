# 2026-10-28 디자인 검수 절차 구축
대상: 검수 도구·CI·배포 | 작성자: Sangwoo Mo(sangwoomo)

> **한줄 결론: 자동 규칙 검사와 별도 시각 검토를 나누고 고정한 수정본의 증거를 배포 조건에 연결한다.**

## 요청
드롭다운 굵기와 보조 정보 크기 같은 문제를 사용자가 반복해서 찾지 않도록 실제 검수 절차를 설정한다.

## 결정과 반영
- 모든 공통 페이지의 실제 크기 화면, 겹치는 스크롤 타일, 상호작용 상태, 공통 컴포넌트 비교를 생성한다.
- 소스·고정 빌드·이미지 해시와 검토자 관찰을 연결한다. 자기 승인·누락·변조·열린 문제·검토 뒤 변경을 거부한다.
- main pre-push 훅과 CI를 연결한다. 성공한 마지막 배포를 기준으로 미검토 디자인이 다음 콘텐츠 갱신에 섞여 배포되지 않게 한다.
- 콘텐츠 자동 갱신은 기존 검사 전부를 유지하고 별도 시각 승인으로 표시하지 않는다. 프로세스 자체 변경도 시각 승인을 꾸미지 않는다.
- 기존 검사는 모두 유지하고 design-audit 보고서와 실행별 고정 화면 artifact를 보관한다.

## 기각한 안과 이유
- 체크리스트만 추가: 실행과 증거 누락을 막지 못한다.
- CSS 기대값만 늘리기: 잘못 정한 크기·굵기도 그대로 통과한다.
- 전체 페이지 축소 캡처: 실제 크기 가독성과 숨은 상태를 확인할 수 없다.
- 구현자의 자기 승인·일괄 긍정 생성: 독립 검토가 아니다.
- 검사와 별개인 legacy 자동 배포 유지: 검사 실패가 실제 배포를 막지 못한다.

## 검증과 남은 것
- 프로세스 회귀 검증에서 미검토·자기 승인·상태와 타일 누락·소스 변경·이미지 변조·재빌드 불일치·미해결 문제·실제 pre-push 차단을 확인했다.
- 전체 캡처 실습, CI 실행, Pages workflow 활성화와 배포 확인은 진행 중이다.
- 원본은 Git 커밋 이력으로 복구한다. 원본 캡처는 `.agent-memory/visual-review/`에 보관한다.

- 첫 전체 실습은 26페이지·4폭·624계획/624캡처·57검토 단위를 생성했다. 페이지 이동 뒤 응답 본문이 해제되는 폰트 기록 오류와 작업 중 소스 변경을 검출해 통과시키지 않았다. 폰트 요청을 렌더 전에 고정해 실제 사용한 바이트를 기록하도록 수정했다.
- 폰트 고정 경로는 실제 Chromium 2개 context와 6회 페이지 이동으로 재검증했고, 회귀 검사 `test_font_evidence.js`를 필수 검사에 넣었다.
